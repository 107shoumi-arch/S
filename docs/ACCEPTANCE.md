# 手機驗收清單

自動化測試與真實裝置驗收是不同結果。這份清單供部署後操作；未實際執行的項目不可標成通過。

## 自動化環境

在專案根目錄執行 `npm run test`、`npm run build` 及 `npm run test:e2e`。瀏覽器測試應覆蓋 375、390、393、430、440 CSS px 寬度及所有五個主要頁面。

檢查測試確實執行，保留成功／失敗／跳過的個別結果，並查看本次產生的截圖。截圖應包含 iPhone 15 Pro Max 對應的 **430 × 932 CSS px** 畫面；瀏覽器視窗模擬不代表真實裝置通過。

測試資料若使用人工固定值，只能作為明確標記的測試案例，不可拿來展示正式行情可用性。

## 真實 iPhone Safari：尚須實機操作

1. 在 iPhone 15 Pro Max 的 Safari 開啟實際 HTTPS 部署網址。確認頂部狀態列／Dynamic Island、底部 Home Indicator 沒有遮住導覽或按鈕。
2. 依序開啟總覽、自選、分析、持倉、設定；每頁上下捲動到最底，最後一項內容仍可完整看見，沒有非必要的水平捲動。
3. 搜尋 `2330` 及中文名稱，核對回傳來源、價格及資料日期。斷網或來源錯誤時，確認沒有被無日期的數字或假即時行情取代。
4. 新增一筆買入，核對「股」與「張」單位；再記錄加碼、部分賣出及股利。對照券商成交單檢查費用及取整差異。
5. 輸入小數價格、負數測試值、超大金額及長名稱，確認驗證訊息清楚、數字沒有被截斷或溢出卡片。
6. 點數字輸入欄位呼叫鍵盤，確認目前欄位及錯誤提示可捲動到看得到的位置；完成輸入後可以收起鍵盤。
7. 調整試算滑桿及精確數字，確認損益立即更新，頁面沒有整頁重新整理，試算輸入不被價格刷新覆蓋。
8. 若有有效歷史 OHLC 資料，檢查 K 線圖在窄螢幕與旋轉後仍符合容器寬度；無資料時應顯示空狀態。
9. 切換深色、淺色及自訂主題，確認漲跌有正負號或文字，不能只靠紅綠辨識；所有文字及表單仍可閱讀。
10. 將手機橫放、再直放。使用 Safari 網頁縮放及 iOS 放大文字設定，確認不以禁止縮放或縮小整頁掩蓋問題。
11. 捲動到頁面中段再刷新行情，確認捲動位置及卡片高度沒有不必要的跳動。
12. 匯出備份，再匯入到另一個測試瀏覽器設定檔；檢查資料完整。不要先清掉唯一一份持倉資料。
13. 依 Safari 分享選單「加入主畫面」，從圖示開啟，確認獨立模式的安全區域與導覽正常。
14. 先連線完整載入，再開啟飛航模式重開 App。檢查離線提示及資料時間，確認不宣稱行情仍在更新。恢復網路後再刷新。
15. 部署新版本後重開 App，確認更新流程能載入新版，持倉仍保留；若清除網站資料測試重裝，先匯出備份。
